# gitblog giscus fork

Fork of https://github.com/giscus/giscus. Original Next.js/React widget, styles, themes and translations are retained; this is not a Svelte rewrite. Upstream MIT license and authorship remain in LICENSE.

Cloudflare OpenNext requires a supported Next.js release, so the fork updates Next.js to 16.4.2 and uses React 18. The Worker is private and is reached through gitblog's service binding at gitblog.app. Do not attach a separate public hostname.

The same gitblog GitHub App is used. Its user token has CMS rights and must NEVER be sent to the original client-side GitHub API functions. Login goes through gitblog's OAuth flow and issues a separate one-hour encrypted, repository-bound comment ticket. The original UI services send that ticket only to allowlisted server operations. The server rechecks public repository and App installation access and validates all comment/reaction node ownership before using the user token. No token endpoint returns the raw GitHub token. Private repositories are unsupported. Creating a missing discussion uses a single-repository Discussions-write installation token after category/repository/title validation; replies and reactions use the visitor credential.

No Supabase, PostgREST or Valkey service is required. Worker secrets: AUTH_SECRET (same as gitblog), GITHUB_PRIVATE_KEY (existing App PEM). Public App IDs are in wrangler.jsonc. Build: npm ci && npm run build:worker. Deploy: npm run deploy. The gitblog Worker routes widget, themes, client.js, _next and the giscus API paths to this Worker.

## Custom Pages domains

Widget framing and GitBlog login callbacks allow the repository owner's `github.io` origin, its explicitly configured Website, and GitBlog itself. If those do not match, the server reads **that repository's** Pages settings. A custom origin is accepted only when `cname` matches the HTTPS `html_url` hostname, `protected_domain_state` is `verified`, HTTPS enforcement is enabled and the certificate is approved. This covers both `name.gitblog.page` and personal domains without a global wildcard allowlist or changing the repository Website. API failures fail closed; `giscus.json` restrictions remain effective.

Only widget origin checks opt into repository-scoped Pages-read tokens, if the installation already has Pages permission. The cache distinguishes these from ordinary comment read/write tokens. No new installation permission is granted by this code, and no installation token is exposed to a browser. GitBlog's `/giscus/login` and legacy `/comments/embed` use the same Pages validation before redirecting a login ticket or setting frame CSP.

The production build uses `next build --webpack` to retain the next-translate loader. Next 15 reached OpenNext's supported-version deadline during this fix; Next 16.4.2 with @opennextjs/cloudflare 1.20.12 builds without bypassing that check. The adapter update includes the preview-props manifest fix needed by Next 16.4. The existing React 18 Pages Router UI is retained. The DOMPurify hook event is imported as a named type for Next 16's bundler module resolution. `npm run test:runtime` starts the built Worker locally and checks a real Next API response plus the client script; CI runs this after the build.

Production verification (2026-10-21): `my-gitblog.gitblog.page` and `shorts-test.gitblog.page` return HTTP 200 with their exact frame ancestor. Requesting the first repository from the second blog origin or a lookalike suffix returns 404 with `frame-ancestors 'none'`. Chrome displayed the existing discussion and completed login back to the original blog with an enabled comment editor; no comment was posted. Personal-domain handling is covered by automated tests, not a separate live personal domain. Main GitBlog passed 1,232 tests; this Worker passed 52 tests, type checks, lint, the OpenNext build and the local workerd runtime smoke test.
